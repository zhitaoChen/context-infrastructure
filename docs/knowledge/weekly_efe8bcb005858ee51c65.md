# 工程操作与评估方法草案

状态：已完成审阅与规则合并（2026-10-19）。本记录保留归纳依据，实际执行以对应规则为准。

三项分别落地：替代安装验证和可比评估合并至 `rules/skills/bestpractice_staged_approach.md`；可验收操作说明合并至 `rules/skills/bestpractice_skill_writing.md` 的操作文档要求。优先更新既有方法，不新增重复 skill。输入支持流程约束，不据此声称效果提升。

## 替代安装先独立验证

**适用范围**：常规升级受阻且存在官方替代发行包的场景。

**方法**：先确认受阻原因、现有版本和启动入口；核对官方发行包完整性，独立测试后再考虑切换入口，保留原有配置。

**验收**：分别检查发行包校验、版本、配置兼容性、各实际启动入口及功能请求；未测试项目单独列明。

**证据与局限**：版本输出不能代替完整验收；输入中的单次可行性描述不能推广为其他软件的验证结论。

## 先验证评估链路，再比较基线

**适用范围**：服务变更或功能实验的效果评估。

**方法**：先以小样本检查请求、响应获取和指标计算；固定输入与评分标准，保留失败和未决结果，与可比基线配对展示，并抽查实际响应及反例。

**验收**：检查链路是否完整、评分是否合理、基线是否可比，以及分数变化是否对应实际质量变化。

**证据与局限**：缺少基线或评分依据时不判断提升；批量或逐条评分需另行确认，流程要求本身不构成实验结果。

## 编写可验收的操作说明

**适用范围**：需要重复执行的启动、修改、构建、部署和验证流程。

**方法**：写明目标、前置条件、执行入口、操作顺序、分支条件、成功检查和常见阻塞处理；仅纳入当前任务所需阶段，缺失信息列为待确认项。

**验收**：检查读者能否找到入口、判断前置条件并区分成功、失败与待确认状态；仅将有验证依据的步骤标为已验证。

**证据与局限**：文档完成不代表流程已执行或验证；缺少环境信息时不补造步骤，具体流程仍须针对目标环境验证，不能以文档已合并代替实际执行验收。
