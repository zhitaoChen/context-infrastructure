## 一分钟了解我们在做什么

我们在把复制来的 `context-infrastructure` 改造成跨项目的 brain/meta library：
保留有价值的继承知识，从自己的实际任务中提炼可迁移的方法，并让 Copilot 按需使用。
目标不是堆满工具，也不是保存全部聊天，而是让日常纠正、验证与经验最终变成可复用知识。

当前已安装全局入口与原生 `personal-brain` skill；Windows 每日自动采集和提炼合格
Copilot 请求，每周生成 skill／公理草稿，审阅后才应用。pi 的树形会话也已接入引用采集，
但原文保留待本地审阅，不能说已经无人值守消化。

主要边界仍在：机器必须保持登录，来源覆盖不是所有设备或所有 Agent；
采集成功不代表方法已提炼，草稿生成不代表已生效。部分知识确实在其他任务中读取过，
但还缺少持续记录“方法改变了什么决定”的应用反馈。本轮规则合并与 pi 接入尚未提交；
本机记忆、配置、原文和工具环境不应上传公开仓库。

## 3. 每日 Observer 与每周 Reflector

执行入口：[run.ps1](../periodic_jobs/ai_heartbeat/run.ps1)。
运行约定详见 [CRONTAB.md](CRONTAB.md)，以下是当前配置快照。

| Windows 任务 | 北京时间 | 执行链路 | 最大执行时限 |
|---|---|---|---|
| `PersonalBrain-Daily` | 每日 00:00 | Copilot 采集 → 已启用 Agent 来源采集 → Observer 提炼 → 候选分类入库 | 42 分钟 |
| `PersonalBrain-Weekly` | 每周日 23:30 | 两类来源采集 → Reflector 比较已接受观察 → 完整草稿 | 22 分钟 |

频率与原仓库的“每日／每周”一致；时刻由原建议的每日 08:00、周日 09:00 调整为
初始化时确认的 00:00、周日 23:30。从 cron／OpenCode 换成 Windows 调度／Copilot，
后续补功能没有改成更高频。

每次模型调用默认最多 600 秒。模型输出结构或本地内容校验失败最多重试一次；
认证、进程错误和超时不按这种方式重试。上表是最坏情况预算，不是每次实际耗时。
Windows 保持登录时锁屏或关闭聊天不影响任务；注销、关机、网络或授权失败仍会阻止运行。
恢复后由 `StartWhenAvailable` 尝试补跑，不保证睡眠唤醒或全天在线。

### Observer 在提炼什么

优先处理新增和较新的待审引用；每次最多检查 5000 条引用，送入模型最多 16 条独立
用户工作流请求，每条最多 4000 字符、最多提炼两条方法。关注明确纠正、证据要求、
可重复工作方式，不把“继续”、自动提示或一次性任务状态当成长期偏好。

本地筛选将疑似敏感、代码/链接、受保护来源等放入 `needs_review`。
筛选不是任意文本绝对安全的保证，不能为了清空队列绕过它。
模型输出与来源版本验证通过后，方法和引用进度一起事务提交；再由每日分类保留或拒绝。

### Reflector 在生成什么

只使用已接受的方法，不直接读取完整聊天。每条候选至少需要两个不同来源的支持；
同一会话内多个请求不冒充多个独立来源，重复要求也不冒充实验效果。

每批最多 128 条观察，优先未审阅内容，并保留最多 32 条已审阅观察作比较。
草稿包括触发/成立条件、操作与验收或反例、证据与局限。不为凑数量强制生成公理，
不自动编辑 rules，不安装工具，也不自动发布或拉取 Git 更新。
