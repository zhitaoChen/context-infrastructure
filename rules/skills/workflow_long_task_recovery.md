# 长任务检查点与恢复

## 目标与验收

用于跨多阶段、预计无法在单次上下文内完成，或用户要求持续执行/恢复的任务。
新会话仅凭检查点和产物即可判断：目标是什么、已完成什么、哪些结果有证据、
下一步执行什么。检查点不是原始对话 dump，也不保证任务一定成功。

## 持久化边界

优先使用目标仓库已有的状态文件或当前会话 artifact 目录；没有时在目标项目
获准的本地目录保存 `checkpoint.json`，通过 `.git/info/exclude` 排除临时状态。
不得把项目源码、数据或详细任务状态复制到中央 brain。
任务目录名需唯一，避免多个 Agent 覆盖同一文件。

检查点至少包含：

```json
{
  "task": "具体目标",
  "updated_at": "ISO-8601 timestamp",
  "status": "in_progress",
  "success_criteria": ["可验证的完成条件"],
  "constraints": ["范围、权限和用户已确认的边界"],
  "completed": [{"step": "已完成阶段", "artifact": "路径", "evidence": "验证结果"}],
  "pending": ["未完成阶段"],
  "next_action": "下一条具体动作",
  "blockers": [],
  "processes": [{"id": "确切 PID 或 agent ID", "purpose": "用途", "status": "最后观察状态"}]
}
```

## 执行与恢复

- 阶段完成、方法改变、出现阻塞，以及结束/压缩上下文前更新检查点。
- 使用临时文件加原子替换，或目标项目已有的事务状态机制。
- 恢复时核对当前工作区与产物是否仍匹配检查点；不要盲信记录的 PID 仍属于原任务。
- 从最后通过验证的阶段继续。重试前确认动作幂等；发布、交易、删除等外部副作用
  必须核对实际结果，不能因日志缺失就重放。
- 子 Agent 持有独立目标、输出位置和停止条件；主 Agent 保留汇总与验收责任。
- 无新证据的重复失败应改变方法或报告阻塞，不无限重试。
- CLI 关闭后子任务可能终止；只有明确安装的外部调度器/服务才提供跨会话执行。

## 持续推进、资源与工作树交接

周期检查核对最终目标、实际新增产物及恢复条件，不把定时器间隔当成工作节拍。可执行的
下一步立即推进；局部阻塞只暂停受影响的副作用，安全独立工作继续。实现保护阈值与授权
边界分开说明，不把自定阈值误作重新授权要求，也不绕过真正的安全约束。

恢复前核对确切writer身份、启动时间、锁与日志，PID存在不等于任务推进。收到共享服务
地址不等于资源已经释放；按约定的释放消息或标记及当前条件验收后才占用。任务完成、
取消或明确交接时，确认本任务无在途写入，处理可能重新占用资源的自动续跑，再发释放信号；
保留未完成阶段。取消定时器与终止业务进程是不同操作，不能混同。

目录锁防重复执行，不证明会话所有权。核对事件来源、承载会话和原授权，不把其他会话的
自动提示当作当前新增授权；消息已送达与对方已完成分别验收。

迁移工作树时同时核对脚本、数据、日志、检查点与定时入口，未知尝试不因路径变化而重放。
构建输出和可写缓存按工作树隔离，保留其他分支增量产物；移植指定改动只迁移净差异，不
夹带实验配置和报告。新入口验证后再切换，保留回退信息，不以安装或路径存在代替功能验收。

## 长期记忆与任务状态分离

检查点保存这次任务的进度；中央记忆只保存经验证且非敏感的通用工程方法。
不要把恢复能力建立在“以后模型应该记得这段聊天”的假设上。
