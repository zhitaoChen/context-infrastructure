# 工作流记忆运行约定

当前执行程序：`tools\brain\history.py`、`observer.py` 与 `memory.py`，仅使用 Python 标准库。
计划任务入口：`periodic_jobs\ai_heartbeat\run.ps1`。

- 采集：用户会话主动提交明确非敏感且有长期价值的工程方法/工作流偏好。
  SQLite 保证提交幂等和并发安全；不得将任意项目数据或整段会话作为输入。
- Observer：授权启用后每日自动从本地引用中筛选独立工作流请求，最多 16 条；
  排除自动提示，将疑似敏感、代码/链接和内部命名空间内容保留为 needs_review。
  使用现有 Copilot 提炼候选，不发送助手输出，不等待交互提醒。
  来源版本及整批输出验证通过后，候选和引用状态在同一事务提交。
- 每日：一次最多处理 32 条 pending，剩余保留到下次。Copilot 只返回 keep/reject
  与理由，本地程序验证完整 ID 集合后事务更新，保留原始证据，不采用模型改写。
- 每周：从已接受条目生成审阅稿，每条提案需至少两个不同来源的证据 ID。
  没有新增输入或来源不足时不调用模型；每批最多 128 条，剩余未审阅输入保留并显示积压。
- Reflector 的 skill / axiom 提案是完整 Markdown 草稿，包含触发或成立条件、
  验收或反例，以及来源证据的实际支持范围。用户的要求不能伪装成实验证实的收益。
  不同会话的独立佐证不能仅因方法相似而被分类器当成重复内容丢弃。
- 后台模型禁止工具和自定义全局指令；不会读取 USER、项目源码或环境配置。
  凭据仅在进程环境中传递，模型不接触；不要在日志或 Git 中保存凭据。
- 每周只输出 review，不修改全局规则，不自动删除已接受记忆。
  用户审阅时核实适用范围、证据独立性、与既有规则是否冲突，再有意编辑对应规则。
- 一个操作系统文件锁串行化后台 worker，关闭/崩溃后自动释放；采集仍可并发提交。
- 格式不合格、认证失败、超时均退出非零并保存失败记录，候选条目不丢失。
  遇到 pending/running 残留可重试；视图可从数据库重建。
- 搜索门槛由本地统计决定，只提示，不自动调用 embedding。

实际数据、运行状态、日志和审阅稿都在 `contexts\memory\.local\`，不提交到 Git。
这里不是金融数据、用户画像或敏感个人信息的长期存储系统。
